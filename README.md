# JARVIS Android

Open this directory in Android Studio and let Gradle sync, or install JDK 17 and Android SDK platform 35 and run:

```sh
./gradlew assembleDebug testDebugUnitTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

For an actual upgrade, sign with the same signing certificate as the installed app. Uninstalling clears app data, including credentials. The debug build generated by Android Studio normally uses its own debug key and may be incompatible with an existing APK. The app retains package `com.raaz.assistant`, preference file `settings`, and Android Keystore alias `jarvis_key`, so existing settings and credentials can be read on a successful in-place upgrade. Keystore migration must be verified on-device.

Under AI Providers enter an HTTPS OpenAI-compatible chat-completions URL, model ID and API key. For Gemini, the URL is `https://generativelanguage.googleapis.com/v1beta/openai/chat/completions`; the provider account must have access to the chosen model. Do not enter keys into issue reports or logs. Keys are AES-GCM encrypted using Android Keystore. Provider configuration is not a connectivity check.

Tap Start to begin foreground turn-based voice, or type. Tap Camera to attach a thumbnail to the next request; a vision-capable model is needed. Spoken replies use the phone's TTS. History is stored locally; remove it from History. Internet connectivity and provider billing/quotas apply.

The app does not provide native real-time audio conversation, streaming replies, audio amplitude/waveform, live camera, autonomous tools, MCP, persistent personal memory, wake word or lock-screen operation. Settings language applies to speech recognition, not a translated app UI. No microphone permission is requested by this app because the external recognizer handles its own permission.

Tests: `./gradlew testDebugUnitTest`; instrumented UI tests: `./gradlew connectedDebugAndroidTest` with an emulator or device. Test API providers, TTS, camera, speech recognition, rotation, font scaling and upgrade migration on actual devices; external services and Android integrations are not covered by the unit tests.

## Voice sessions (prompt 02)

Tap Start and grant microphone access. In the foreground, Android's `SpeechRecognizer` supplies partial and final transcripts and RMS estimates. The recognizer's own service handles speech start/end, silence and background noise; its behavior and online/offline availability vary by device. Final text is sent to the saved text-chat provider, Android TTS reads the answer, and listening resumes after TTS completes. Silence/no-match starts another recognition turn after a short backoff. A speech or provider error stops the session and shows a message. Tap Stop to release recognition and TTS and cancel the pending HTTP request; moving the app to the background also stops the session. Android output routing (including supported headsets) remains system controlled.

Only turn-based voice is implemented. There is no native real-time provider/WebRTC integration, audio input/output streaming, realtime ephemeral-key backend, simultaneous listening and speaking, or barge-in. The mic is not listened to during TTS; the UI reports this limitation. Real microphone values are supplied only when the Android recognizer reports RMS; TTS amplitude is unavailable. Reconnection applies only to silence/no-match recognition turns; a network or audio-focus interruption ends the session and requires Start again. Voice replies require a working Android TTS engine. Provider connection testing sends an actual text request, which may consume quota.

Manual verification on an Android device with a speech recognizer, TTS engine and configured provider: (1) accept and deny RECORD_AUDIO permission, checking the denial message; (2) Start, speak a greeting, hear a real reply, then ask another question without touching Start; (3) verify transcript/RMS and processing/speaking/listening indicators; (4) tap Stop during recognition, request and speech, checking that audio and session stop; (5) background the app, rotate it, interrupt with a phone call, disconnect the network and check that no undisclosed microphone session survives; (6) try provider connection test, photo attachment and regular text chat. None of these live Android or provider tests were performed in this workspace.

## Provider profiles and text streaming (prompt 03)

AI Providers supports multiple profiles, selection, editing, deletion, encrypted keys and an actual inference connection test. Existing single-provider settings and key are shown as the legacy profile and remain in their existing storage. Choose a preset or enter an HTTPS OpenAI-compatible Chat Completions endpoint, model and credential. Enable SSE only when your chosen endpoint/model supports the OpenAI-compatible streaming protocol. Changing an existing endpoint requires a new key. Custom services receive your key, prompts and any image you send; use trusted hosts only. Models must be entered manually. Connection results reset at restart.

Streaming is real SSE, not simulated. A missing SSE completion marker is treated as an interrupted response; partial text is discarded rather than stored or spoken. There is no automatic retry or fallback, provider-native Gemini adapter, realtime audio, verified usage reporting, message timestamps, markdown, copy control or failed-request retry. The provider presets and voice flow have not been tested against real accounts or Android hardware. See PROVIDER-AUDIT.md for migration and limitations.

# Provider integration audit and limitations

The supplied project had a single OpenAI-compatible non-streaming HTTP adapter, one saved endpoint/model/key, and no profile selection. It stores its AES-GCM encrypted credential in `settings`/`secret` using Android Keystore `jarvis_key`. SpeechRecognizer and Android TTS implement a foreground turn-based loop, not native realtime audio. Streaming, timestamps and genuine provider usage metrics were absent. Errors mostly reported an HTTP number, and connection cancellation was not guarded by a request generation.

The new implementation keeps package ID, settings, conversation history and the legacy keystore/key fields. The old profile is exposed as `Existing provider`; it reads the existing credential without deleting it. Additional profiles store separate AES-GCM encrypted key values using the same Android Keystore key. Changes must be verified on an actual in-place upgrade signed with the original certificate. User-configured providers receive the key and conversation, so trust the provider. HTTPS endpoints with user info, fragments or query strings are rejected; redirects are disabled.

The current adapter uses OpenAI-compatible Chat Completions bearer authentication and optional SSE `data:` streaming. Presets use OpenAI, NVIDIA NIM, and Gemini OpenAI compatibility URLs; only compatible text models and endpoints are supported. It does not implement Gemini native API, provider-specific audio APIs, OAuth, realtime sessions or a backend. Streaming is opt-in and not capability-discovered; unsupported providers should have streaming disabled manually. A test sends one actual non-streaming model inference and may incur usage. Connection results are in-memory and reset on restart.

There is no automatic retry or automatic streaming fallback, avoiding duplicate billable requests. No usage totals, latency, model discovery, markdown/code-block rendering, message timestamps, failed-request retry or response-copy control are implemented. Partial replies are not saved after cancellation or stream errors. Network cancellation requests disconnect, but real cancellation behavior depends on Android networking and must be verified on-device. Saved history remains local, unencrypted app-private data with backup disabled. No live provider or Android device was available to validate compatibility, credential migration, UI, voice or streaming.
